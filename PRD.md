# PRD: Livigno – mountain adventure all year round

Student project – Internet Technologies (Client Side), CZU Prague, 2026.
Authors: Magadeline Ndlovu, Sobin Karakkunnummel, Gayathri Devi Shalini Dileep, Monika Tasheva.

## 1. Goal
A regional tourism website that helps visitors plan a trip to Livigno in summer or winter:
what to do, what to eat, how to get there, and what is on.

## 2. Users
- Holiday visitors (families, couples) planning a summer or winter trip
- Sport visitors (hikers, cyclists, skiers, snowboarders)
- Visitors who use a screen reader, a keyboard only, or a browser with JavaScript turned off

## 3. Technical scope
- Static HTML5, CSS3 (Flexbox + Grid) and plain JavaScript (ES modules); no front-end framework
- Shared header and footer generated by `src/build.mjs` (Node, standard library only)
- Data in `data/*.json`, loaded with `fetch()` through `js/api.js` (ready for a back end)
- Third-party APIs: Open-Meteo (weather), OpenStreetMap (map embed)
- Hosting: GitHub Pages
- Test packages only: `@playwright/test`, `@axe-core/playwright` (versions pinned in `package.json`)

## 4. Out of scope
- Log-in, user accounts, passwords
- Bookings, payments, ski-pass sales
- A real back end or database (planned for next semester)
- Sending e-mails (the contact form only validates)
- Other languages than English

## 5. Increments

### P1: Pages and navigation – status: done
Story: As a visitor, I want a clear menu so that I can reach every section from any page.
- When the window is under 600 px wide, then a bottom navigation bar is shown.
- When it is 600–839 px, then a navigation rail is shown; from 840 px, top tabs are shown.
- When I am on a page, then its menu item has `aria-current="page"`.

### P2: Trails with search and filters (AJAX) – status: done
Story: As a hiker, I want to filter trails by activity and difficulty so that I find a suitable one.
- When I choose the Hiking chip, then only hiking trails are shown.
- When no trail matches, then a "Clear filters" button brings all trails back.
- When I save a trail, then it appears in "Plan my day" and stays after a reload.

### P3: Live weather (third-party API) – status: done
Story: As a skier, I want to see current weather and snow so that I can decide when to go.
- When the Open-Meteo API answers, then temperature, snow, wind and an "Updated" time are shown.
- When the API fails, then a clear message is shown instead of empty values.

### P4: Events with microformats – status: done
Story: As a visitor, I want a list of events so that I can plan my dates.
- When I open plan.html#tab-events, then the Events tab is selected and shows 6 events.
- When the page is parsed, then each event is an `h-event` and the tourist office is an `h-card`.

### P5: Contact form – status: done
Story: As a visitor, I want to ask the tourist office a question.
- When I send the empty form, then each field shows an error and focus moves to the first one.
- When the form is filled in correctly, then a thank-you message appears.

### P6: Real photos and credits – status: done (2 placeholders left)
Story: As a visitor, I want real photos so that I can imagine the place.
- When a photo is used, then it has a free licence and a credit on sources.html.
- When a photo is not found yet, then a labelled placeholder is shown.

### P7: Works without JavaScript – status: done
Story: As a visitor with JavaScript turned off, I want to read all content.
- When JavaScript is off, then all tab sections are visible with their own headings.
- When JavaScript is off, then the 6 trails and 6 events are still listed.
- When JavaScript is off, then controls that need it (filters, switches, form) are hidden and a short note explains the alternative.

### P8: New colour scheme – status: done
Story: As a visitor, I want a fresh, friendly look.
- When a page opens, then it uses baby blue, light green and grey.
- When axe checks colour contrast, then there are 0 violations.

### P9: Back end – status: planned (next semester)
Story: As the tourist office, I want to manage trails and events and receive contact messages.

## 6. Decisions and changes
| Date | Decision | Why |
|---|---|---|
| 2026-11-08 | Static pages from a build script instead of a framework | Fast pages, no dependencies, easy to validate |
| 2026-11-11 | Layout inspired by livigno.eu, but own texts, logo and colours | Requested by the team; no copying of brand or content |
| 2026-11-11 | Removed a watermarked iStock photo and a photo of the wrong dish | Licence and content check in review |
| 2026-11-11 | Added a hidden h2 on the Plan page | W3C checker found a skipped heading level |
| 2026-11-11 | Compressed photos to 800 px | Lighthouse: Home mobile performance was 82 |
| 2026-11-11 | Moved the repository to the `livigno-explorers` organization | A group project should not live under one person's name |
| 2026-11-12 | Progressive enhancement: content in HTML, JavaScript only adds features | Lecture: the site must be usable without JavaScript |
| 2026-11-12 | Added Playwright end-to-end tests with axe | Lecture: "automated tests pass" is part of the DoD |
| 2026-11-12 | New colours: baby blue, light green, grey | Team found the old design too plain |
